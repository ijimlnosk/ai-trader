# Backend foundation

Composition is owned by `apps/server/src/app`: validated environment, database resource lifecycle,
Fastify creation and signal shutdown. `interfaces/http` maps the application health result to HTTP.
`application/health.ts` depends on DatabaseHealth and Broker ports; PostgreSQL and PaperBroker implement
these contracts in infrastructure. `domain/tradingSafety.ts` is a pure configuration gate.
No domain entity is needed yet; database records are not domain entities.

Public shared API contracts live in `@ai-trader/contracts`. Shared strict compiler configuration
lives in `@ai-trader/config`. Package exports prevent imports of package implementation paths.
ESLint restricts outward dependencies from domain/application. No execution, AI, risk engine, account-data query or order HTTP endpoint exists.
Read-only KIS authentication and domestic quote integration is implemented below.

Startup checks the database before listening. Runtime health rechecks connectivity with bounded
connection/query timeouts and returns 503 on failure. Logs omit raw environment and driver errors.
SIGINT/SIGTERM close Fastify and the PostgreSQL pool, with a ten-second shutdown deadline.

Paper is the default. `hasLiveTradingOptIn` requires BOTH explicit switches, but it is only a
necessary configuration condition, never order authorization. This build rejects ALL live broker
configurations. The health Broker port exposes mode identity; the separate MarketBroker port owns read-only quotes.

PostgreSQL 17 schema uses UUID primary keys, timestamptz instants, decimal strings mapped from
numeric(24,8), explicit three-letter currency codes, and shares as quantity units. Prices and money
are expressed in the recorded currency; no JS float arithmetic exists. Positions currently represent
long holdings. Score is 0–100; confidence is 0–1. Risk is descriptive text, not a risk-engine decision.
Orders reference proposals with RESTRICT deletion and allow BUY/SELL only; proposals also allow HOLD.
Order price is required (no market-order semantics yet). updated_at must be explicitly updated by future
repository writes; its default applies only on insert. No table is written by the running application.

Migrations are checked-in SQL generated by Drizzle Kit and applied only by explicit command.
The runtime image carries a compiled migration entrypoint, not development dependencies.
Compose uses an existing external named volume and exposes only loopback port 3200 for HTTP.
An existing database must remain under its existing Compose project/service/network ownership.

## KIS paper market data

`app/createApp.ts` composes `application/market.ts` with `infrastructure/broker/kis`.
The application owns MarketBroker and safe BrokerError contracts; domain Quote has no provider fields.
HTTP routes depend on application use cases; shared QuoteResponse/BrokerStatusResponse describe the API.
The existing database `/health` remains independent of KIS availability.

The adapter contains a bounded fetch client, Zod response schemas, a token provider and quote mapping.
Only `https://openapivts.koreainvestment.com:29443` is accepted at startup and at the transport boundary.
Redirects are rejected and each request has a ten-second timeout. No automatic HTTP retry is performed.
App key/secret come only from validated environment. Account variables are accepted and passed through
Compose but are not needed for token/quote requests and never leave composition.

Tokens are process-local, reused until 60 seconds before expires_in (measured from issuance start).
Concurrent issuance shares one Promise; failure clears it for a later request. Authentication rejection
invalidates the corresponding cached token for the next request without replaying the failed request.
Restarting or using multiple server processes creates separate caches; Redis and distributed coordination
are outside this phase. Provider bodies, credentials and raw exceptions are never logged or returned.

`GET /api/v1/market/:symbol/quote` validates exactly six ASCII digits and maps KIS price/change to KRW
strings, changeRate to percentage strings (1.5 means 1.5%), volume to cumulative share strings.
`timestamp` is server receipt time in UTC, NOT trade time or a guarantee of market-data freshness.
`GET /api/v1/broker/status` reports provider, paper mode, credential completeness and reachability.
It returns HTTP 200 for an inspected status, including failed connectivity; failure adds a safe error code.
With credentials it performs a real 005930 quote request each time, sharing the token cache.
It does not merely infer reachability from a locally cached token. Unconfigured status makes no request.

Quote errors distinguish invalid_symbol (400), configuration_error (503), authentication_error (502),
provider_unavailable (503), provider_invalid_response (502). Unexpected errors are sanitized to 500.
An upstream authentication failure is 502 rather than implying the API caller's authentication failed.
No buy/sell/order/cancel/amend, balance, execution, risk or AI methods are introduced.
