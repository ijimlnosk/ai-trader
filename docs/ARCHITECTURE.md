# Backend foundation

Composition is owned by `apps/server/src/app`: validated environment, database resource lifecycle,
Fastify creation and signal shutdown. `interfaces/http` maps the application health result to HTTP.
`application/health.ts` depends on DatabaseHealth and Broker ports; PostgreSQL and PaperBroker implement
these contracts in infrastructure. `domain/tradingSafety.ts` is a pure configuration gate.
No domain entity is needed yet; database records are not domain entities.

Public shared API contracts live in `@ai-trader/contracts`. Shared strict compiler configuration
lives in `@ai-trader/config`. Package exports prevent imports of package implementation paths.
ESLint restricts outward dependencies from domain/application. No execution, AI, risk engine,
provider integration, account data, or trading HTTP endpoint exists.

Startup checks the database before listening. Runtime health rechecks connectivity with bounded
connection/query timeouts and returns 503 on failure. Logs omit raw environment and driver errors.
SIGINT/SIGTERM close Fastify and the PostgreSQL pool, with a ten-second shutdown deadline.

Paper is the default. `hasLiveTradingOptIn` requires BOTH explicit switches, but it is only a
necessary configuration condition, never order authorization. This build rejects ALL live broker
configurations. Broker exposes only mode identity until executable use cases justify more methods.

PostgreSQL 17 schema uses UUID primary keys, timestamptz instants, decimal strings mapped from
numeric(24,8), explicit three-letter currency codes, and shares as quantity units. Prices and money
are expressed in the recorded currency; no JS float arithmetic exists. Positions currently represent
long holdings. Score is 0–100; confidence is 0–1. Risk is descriptive text, not a risk-engine decision.
Orders reference proposals with RESTRICT deletion and allow BUY/SELL only; proposals also allow HOLD.
Order price is required (no market-order semantics yet). updated_at must be explicitly updated by future
repository writes; its default applies only on insert. No table is written by the running application.

Migrations are checked-in SQL generated by Drizzle Kit and applied only by explicit command.
The runtime image carries a compiled migration entrypoint, not development dependencies.
Compose uses an existing external named volume and exposes only loopback port 3200 for HTTP.
An existing database must remain under its existing Compose project/service/network ownership.
